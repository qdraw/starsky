# Starsky Connect — Swift implementation spec (iOS & macOS)

This document specifies how to port the `starsky.foundation.connect` and
`starsky.feature.connect` C# libraries to a native Swift package that runs on
iOS 17+ and macOS 14+. The wire protocol (BEP v1) and overall architecture are
identical to the C# side; this spec covers the platform-specific translation
decisions.

---

## Scope

| In scope | Out of scope |
|---|---|
| BEP v1 protocol framing (Hello, post-auth messages) | Relay client (phase 2) |
| TLS transport via Network.framework | Global discovery (phase 2) |
| Device identity (cert gen, Device ID) | UI preferences screen |
| Local UDP multicast discovery | Admin REST API |
| Config + cert persistence (Keychain + SQLite) | |
| Block exchange (Scanner, BlockStore, Downloader) | |
| Conflict resolution | |
| Background sync on iOS | |

---

## Target platforms

| Platform | Minimum | Swift |
|---|---|---|
| macOS | 14.0 (Sonoma) | 5.10 |
| iOS / iPadOS | 17.0 | 5.10 |
| visionOS | 1.0 (opportunistic) | 5.10 |

Strict concurrency (`-strict-concurrency=complete`) must be enabled from the
start. Every type that crosses actor boundaries must be `Sendable`.

### `DeviceIdentity.swift`

```swift
import CryptoKit
import Security

public enum DeviceIdentity {
    /// Generates a new RSA-2048 self-signed certificate and returns the
    /// SecIdentity (private key + cert). Stored in the Keychain by the caller.
    public static func generateIdentity(label: String = "starsky-connect") throws -> SecIdentity

    /// Derives the 63-character hyphen-grouped Syncthing Device ID from a certificate.
    public static func deriveDeviceId(from cert: SecCertificate) throws -> String

    /// Derives the raw 32-byte device-ID bytes (SHA-256 of DER-encoded cert).
    public static func deriveDeviceIdBytes(from cert: SecCertificate) throws -> Data

    /// Normalises a user-supplied Device ID: strip hyphens, uppercase,
    /// replace 0→O, 1→I, 8→B.
    public static func normalize(_ deviceId: String) -> String

    /// Validates the Luhn-mod-N checksum on each group.
    public static func isValid(_ deviceId: String) -> Bool
}
```

**Key difference from C#:** `SecKeyGeneratePair` / `SecCertificateCreateWithData`
replace `RSA.Create()` / `CertificateRequest`. The private key lives in the
Keychain under a fixed `kSecAttrLabel`; there is no PFX export — the cert's
DER bytes are stored in SQLite (mirroring the DB approach on the C# side).

## Protocol — `StarskyConnectFoundation/Protocol/`

### Proto generation

Add the `.proto` file (identical to the C# one, minus the `csharp_namespace`
option) to `Sources/StarskyConnectFoundation/Protocol/`. Run:

```bash
protoc --swift_out=. --swift_opt=Visibility=Public bep.proto
```

Add the generated `bep.pb.swift` to the target. The `option swift_prefix = "Bep"` 
avoids name collisions with Foundation types.

### `BepFraming.swift`

Replaces `BepReader.cs` + `BepWriter.cs`.

```swift
import Foundation

public actor BepFraming {
    private let connection: NWConnection  // Network.framework

    // ── Hello ──────────────────────────────────────────────────────────────

    public func writeHello(_ hello: BepHello) async throws
    public func readHello() async throws -> BepHello

    // ── Post-auth ──────────────────────────────────────────────────────────

    /// Reads one BEP frame; decompresses if LZ4.
    public func readMessage() async throws -> BepMessage

    /// Serialises message, optionally LZ4-compresses, writes frame.
    /// Compression threshold: only compress if body > 128 bytes AND
    /// compressed size < 96.875 % of original.
    public func writeMessage<M: Message>(
        _ message: M,
        type: BepHeader.TypeEnum,
        compress: Bool = false
    ) async throws
}

public struct BepMessage: Sendable {
    public let header: BepHeader
    public let body: Data   // already decompressed

    public func parse<M: SwiftProtobuf.Message>(_ type: M.Type) throws -> M {
        try M(serializedBytes: body)
    }
}
```

**Why `actor`?** Every `NWConnection` send/receive is already async on its
own `DispatchQueue`; wrapping in an actor gives automatic mutual exclusion for
the write side (matching the `SemaphoreSlim(1,1)` in C#) without explicit
locking.

**Frame format** (identical to C#):
- Hello: 4-byte magic `0x2EA7D90B` (BE) + UInt16 length (BE) + protobuf body
- Post-auth: UInt16 header length (BE) + header protobuf + UInt32 body length (BE) + body

### `Compression.swift`

LZ4 is not in the Apple SDK. Options (pick one):

1. **Thin C shim** (recommended): add `lz4.c` and `lz4.h` from the reference
   implementation to a `CLZ4` target in the package. Swift calls it via
   `import CLZ4`.
2. **`Compression` framework** (`COMPRESSION_LZ4`): available on Apple
   platforms, but uses the LZSS-variant block format, not the raw LZ4 frame.
   The raw block format with a 4-byte uncompressed-length prefix is what BEP
   uses — verify byte-level compatibility before choosing this option.

```swift
import CLZ4   // thin C shim

public enum BepCompression {
    /// Prepends 4-byte little-endian uncompressed length, then LZ4-compresses.
    public static func compress(_ data: Data) throws -> Data

    /// Reads 4-byte uncompressed length prefix, then LZ4-decompresses.
    public static func decompress(_ data: Data) throws -> Data
}
```

## Transport — `StarskyConnectFoundation/Transport/`

### TLS via Network.framework

`Network.framework` (`NWConnection`, `NWListener`, `NWParameters`) replaces
`SslStream` / `TcpClient`. The mTLS setup:

```swift
// Build TLS parameters that present our identity and accept any peer cert
// (device-ID validation happens in the verify callback, not CA chain).
func makeTLSParameters(identity: SecIdentity, allowedDeviceIds: Set<String>) -> NWParameters {
    let tls = NWProtocolTLS.Options()

    sec_protocol_options_set_min_tls_protocol_version(
        tls.securityProtocolOptions, .TLSv12)

    // Present our cert
    sec_protocol_options_set_local_identity(
        tls.securityProtocolOptions,
        sec_identity_create(identity)!)

    // Custom peer verification: accept any cert; check device ID against allow-list
    sec_protocol_options_set_peer_authentication_required(
        tls.securityProtocolOptions, false)

    sec_protocol_options_set_verify_block(
        tls.securityProtocolOptions,
        { metadata, trust, completion in
            let peerCert = sec_trust_copy_leaf_certificate(trust)!
            let derived = try? DeviceIdentity.deriveDeviceId(
                from: sec_certificate_copy_ref(peerCert).takeRetainedValue())
            let normalized = derived.map { DeviceIdentity.normalize($0) } ?? ""
            completion(allowedDeviceIds.contains(normalized))
        },
        .main)

    return NWParameters(tls: tls, tcp: NWProtocolTCP.Options())
}
```

> **macOS note:** `NWListener` needs the `com.apple.security.network.server`
> entitlement (already present in `starsky.entitlements`) and the Firewall
> dialog will appear on first listen.

> **iOS note:** background TCP connections require the `voip` background mode
> (or use a `NWPathMonitor`-gated reconnect when foregrounded). See the
> Background sync section.

### `ConnectionManager.swift`

```swift
public actor ConnectionManager {
    // Keepalive intervals (same as C#)
    private static let pingSendInterval: Duration = .seconds(90)
    private static let receiveTimeout:   Duration = .seconds(300)
    private static let pingCheckInterval: Duration = .seconds(45)
    private static let minReconnectDelay: Duration = .seconds(5)
    private static let maxReconnectDelay: Duration = .seconds(1800)

    private var connections: [String: BepConnection] = [:]  // normalized device ID → conn
    private var outboundPeers: [String: [String]] = [:]     // device ID → addresses

    // Callbacks (use AsyncStream or structured tasks instead of Func<> delegates)
    public var onPeerConnected: AsyncStream<(deviceId: String, hello: BepHello)>
    public var onMessageReceived: AsyncStream<(deviceId: String, message: BepMessage)>
    public var onPeerDisconnected: AsyncStream<(deviceId: String, error: Error?)>

    public func addPeer(deviceId: String, addresses: [String]) async
    public func send<M: SwiftProtobuf.Message>(
        to deviceId: String,
        _ message: M,
        type: BepHeader.TypeEnum,
        compress: Bool = false) async throws
    public func start() async throws
    public func stop() async

```

**Key difference from C#:** replace `Func<…, Task>` callbacks with
`AsyncStream` so callers can `for await` them in structured concurrency tasks.

## Discovery — `StarskyConnectFoundation/Discovery/`

### `LocalDiscovery.swift`

UDP multicast on `239.255.68.42:21027` (IPv4) and `[ff12::8384]:21027` (IPv6).

```swift
import Network

public actor LocalDiscovery {
    private static let ipv4Group = NWEndpoint.hostPort(
        host: "239.255.68.42", port: 21027)
    private static let ipv6Group = NWEndpoint.hostPort(
        host: "ff12::8384", port: 21027)

    private var instanceID: UInt64 = .random(in: .min ... .max)
    // cache: device ID → (addresses, expiry)
    private var cache: [String: (addresses: [String], expires: ContinuousClock.Instant)] = [:]

    /// Broadcast our own addresses; cache peers. Runs until cancelled.
    public func run(
        myDeviceId: String,
        myAddresses: [String]
    ) async throws

    /// Returns cached addresses for `deviceId`, nil if expired or unknown.
    public func lookup(deviceId: String) -> [String]?
}
```

Use `NWConnection` in UDP mode with `NWParameters.udp` and multicast group
membership via `setsockopt(IP_ADD_MEMBERSHIP)` through a raw BSD socket
(Network.framework does not expose multicast join APIs directly — use
`CFSocket` or a `NWConnectionGroup` with a multicast descriptor).

The announce payload is:
- 4-byte magic `0x2EA7D90B` (big-endian)
- protobuf-encoded `BepAnnounce` (already in `bep.proto`)

Re-announce every 30 s. Expire cache entries after 90 s.

## Storage — `StarskyConnectFoundation/Storage/`

### Certificate storage

**Do not store the private key in a JSON file or the SQLite database.**
Use the Keychain on both macOS and iOS:

| C# | Swift |
|---|---|
| PFX Base64 in `ApplicationDbContext.Settings` | `SecIdentity` in Keychain (`kSecAttrLabel = "starsky-connect-identity"`) |

## Sync engine — `StarskyConnectFeature/Sync/`

### `Scanner.swift`

```swift
import Foundation

public actor Scanner {
    private let folderRoot: URL
    private let db: DatabaseQueue

    /// Full scan: walk all files, hash blocks, upsert ConnectFileMeta +
    /// ConnectBlockInfo. Returns the set of changed file names.
    public func fullScan() async throws -> Set<String>

    /// Incremental: re-hash one file and upsert its records.
    public func scanFile(relativePath: String) async throws

    /// Returns a BEP FileInfo message ready to send in Index/IndexUpdate.
    public func buildFileInfo(relativePath: String) async throws -> BepFileInfo?
}
```

Block hashing uses `CryptoKit.SHA256`:

```swift
func hashBlock(_ data: Data) -> Data {
    Data(SHA256.hash(data: data))
}
```

Block sizing mirrors the C# `BlockSizing`:

```swift
func selectBlockSize(fileSize: Int64) -> Int {
    let min = 128 * 1024, max = 16 * 1024 * 1024
    var size = min
    while size < max && fileSize / Int64(size) >= 2000 { size <<= 1 }
    return size
}
```

Uses `FileHandle` for random-access writes. The temp path scheme matches C#:

### `Downloader.swift`

```swift
public actor Downloader {
    private let connectionManager: ConnectionManager
    private let blockStore: BlockStore

    // Limit concurrent outstanding requests to 128 (Syncthing default)
    private var outstandingSlots = 128
    private var pending: [Int32: CheckedContinuation<BepResponse, Error>] = [:]

    /// Called by SyncEngine when a Response arrives.
    public func receiveResponse(_ response: BepResponse)

    /// Downloads all blocks from `deviceId`; writes to BlockStore.
    public func downloadFile(
        deviceId: String,
        folderId: String,
        folderRoot: URL,
        name: String,
        blocks: [BepBlockInfo]
    ) async throws -> Bool
}
```

Use `withCheckedThrowingContinuation` instead of `TaskCompletionSource`:
each block request suspends until `receiveResponse` resumes the continuation.
A 60-second deadline uses `withTimeout` (or a child task with `Task.sleep`).

### `ConflictResolver.swift`

```swift
public struct ConflictResolver {
    public func renameToConflict(at url: URL, deviceId: String) throws -> URL {
        let stem = url.deletingPathExtension().lastPathComponent
        let ext = url.pathExtension
        let shortId = String(deviceId.filter { $0 != "-" }.prefix(7))
        let timestamp = ISO8601DateFormatter().string(from: .now)
            .replacingOccurrences(of: "T", with: "-")
            .replacingOccurrences(of: ":", with: "")
            .replacingOccurrences(of: "Z", with: "")
            .prefix(15)
        let newName = "\(stem).sync-conflict-\(timestamp)-\(shortId).\(ext)"
        let dest = url.deletingLastPathComponent().appending(path: newName)
        try FileManager.default.moveItem(at: url, to: dest)
        return dest
    }
}
```

### `SyncEngine.swift`

The top-level orchestrator. On macOS it runs as a `Task` started by the app;
on iOS it lives inside a `BGProcessingTask` (see Background sync).

```swift
public actor SyncEngine {
    private let connectionManager: ConnectionManager
    private let configStore: ConfigStore
    private let downloader: Downloader
    private let scanner: Scanner
    private let conflictResolver = ConflictResolver()

    // BEP state per peer: .waitingForClusterConfig | .ready
    private var peerState: [String: PeerState] = [:]

    public func start() async throws
    public func stop() async

    // ── Message dispatch ───────────────────────────────────────────────────

    private func handle(_ msg: BepMessage, from deviceId: String) async throws
    private func handleClusterConfig(_ cc: BepClusterConfig, from deviceId: String) async throws
    private func handleIndex(_ idx: BepIndex, from deviceId: String) async throws
    private func handleIndexUpdate(_ upd: BepIndexUpdate, from deviceId: String) async throws
    private func handleRequest(_ req: BepRequest, from deviceId: String) async throws
    private func handleResponse(_ res: BepResponse) async
    private func handleClose(_ close: BepClose, from deviceId: String) async
}
```

**Index consistency checks** (mirror C# `checkIndexConsistency`):
- `FileInfo.name` must not be empty and must use `/` separators only
- Deleted files must have empty `blocks`
- Directories and symlinks must have empty `blocks` and zero `size`
- `localFlags` field 1000 must never appear on the wire

## File watching — `StarskyConnectFeature/Watchers/`

### `FileWatcher.swift`

The `LocalChangeSource` protocol decouples the sync engine from the concrete
watcher implementation so the same `SyncEngine` code runs on both platforms.

```swift
public protocol LocalChangeSource: AnyObject, Sendable {
    var changes: AsyncStream<LocalChange> { get }
}

public struct LocalChange: Sendable {
    public enum Kind { case created, modified, deleted, renamed(from: String) }
    public let relativePath: String
    public let kind: Kind
}
```

**macOS — `FSEventsWatcher`**

Uses the CoreServices `FSEvents` C API directly (not `DispatchSource`, which
only watches a single file descriptor and is unsuitable for recursive directory
watching):

```swift
public final class FSEventsWatcher: LocalChangeSource {
    private let root: URL
    private var streamRef: FSEventStreamRef?
    private let continuation: AsyncStream<LocalChange>.Continuation

    public init(root: URL) throws {
        // FSEventStreamCreate with kFSEventStreamEventFlagItemIsFile |
        // kFSEventStreamEventFlagItemRenamed, latency 1.0 s, sinceNow
    }

    public func start() {
        FSEventStreamScheduleWithRunLoop(streamRef!, CFRunLoopGetMain(), CFRunLoopMode.defaultMode.rawValue)
        FSEventStreamStart(streamRef!)
    }

    public func stop() {
        FSEventStreamStop(streamRef!)
        FSEventStreamInvalidate(streamRef!)
        FSEventStreamRelease(streamRef!)
    }
}
```

**iOS — `NSFilePresenterWatcher`**

iOS does not expose `FSEvents`. The correct approach for an App Group container
is `NSFilePresenter`, which the system calls whenever any process (including
extensions) modifies files the presenter has registered:

```swift
public final class NSFilePresenterWatcher: NSObject, NSFilePresenter, LocalChangeSource {
    public let presentedItemURL: URL?
    public let presentedItemOperationQueue = OperationQueue.main

    // NSFilePresenter callbacks
    public func presentedSubitemDidChange(at url: URL) {
        let rel = url.path.removingPrefix(root.path + "/")
        continuation.yield(LocalChange(relativePath: rel, kind: .modified))
    }

    public func accommodatePresentedSubitemDeletion(
        at url: URL, completionHandler: @escaping (Error?) -> Void
    ) {
        let rel = url.path.removingPrefix(root.path + "/")
        continuation.yield(LocalChange(relativePath: rel, kind: .deleted))
        completionHandler(nil)
    }
}
```

Register it with `NSFileCoordinator.addFilePresenter(_:)` on init and remove
it in `deinit`. The coordinator ensures that writes from other extensions are
visible before the callback fires — critical when a File Provider Extension
downloads a file and the main app's watcher needs to pick it up.

`SyncEngine` depends only on `LocalChangeSource`, not on a concrete watcher.

## Background sync on iOS

iOS suspends apps within seconds of going to background and tears down TCP
connections. The C# `ConnectionManager`'s persistent read-loop cannot survive
in this environment. The strategy:

### Lifecycle table

| Event | Action |
|---|---|
| App becomes active (`sceneDidBecomeActive`) | Call `SyncEngine.start()` — connects all peers, exchanges ClusterConfig + Index |
| App enters background (`sceneDidEnterBackground`) | Call `SyncEngine.stop()` — tears down connections cleanly (sends BEP `Close`), then schedules a `BGProcessingTask` |
| `BGProcessingTask` fires (OS-chosen moment, typically on power) | Runs `SyncEngine` for up to 30 s; flushes any queued IndexUpdate messages |
| Silent APNs push `content-available: 1` (optional, requires server support) | Wakes app in background for ~30 s via `application(_:didReceiveRemoteNotification:)` |
| `NWPathMonitor` detects network path available | If app is foreground, reconnect immediately; if background, rely on the BGTask schedule |

### `BGProcessingTask` setup

```swift
// In AppDelegate.application(_:didFinishLaunchingWithOptions:)
BGTaskScheduler.shared.register(
    forTaskWithIdentifier: "nl.greenchoice.starsky.connect-sync",
    using: nil
) { task in
    guard let task = task as? BGProcessingTask else { return }

    // Cancel sync when the OS reclaims the budget
    task.expirationHandler = {
        Task { await SyncEngine.shared.stop() }
    }

    Task {
        try? await SyncEngine.shared.runBackgroundSync()
        task.setTaskCompleted(success: true)
        scheduleNextBackgroundSync()  // reschedule for next opportunity
    }
}

func scheduleNextBackgroundSync() {
    let request = BGProcessingTaskRequest(
        identifier: "nl.greenchoice.starsky.connect-sync")
    request.requiresNetworkConnectivity = true
    request.requiresExternalPower = false  // allow on battery too
    request.earliestBeginDate = Date(timeIntervalSinceNow: 15 * 60)  // no sooner than 15 min
    try? BGTaskScheduler.shared.submit(request)
}
```

**Required entitlements and Info.plist:**

```xml

</array>
```


### `SyncEngine.runBackgroundSync()`

```swift
extension SyncEngine {
    /// Runs a time-limited sync pass. Connects, exchanges Index, downloads
    /// pending files, then disconnects. Designed for BGProcessingTask.
    func runBackgroundSync(timeLimit: Duration = .seconds(25)) async {
        do {
            try await start()
            try await Task.sleep(for: timeLimit)  // yield to incoming messages
        } catch {}
        await stop()
    }
}
```

## App Group container

An App Group lets the main Starsky app, the Connect sync engine, and a future
File Provider Extension share the same SQLite database and synced-file directory
without XPC round-trips.

**Group ID:** `group.nl.greenchoice.starsky`

**Container layout:**

```
group.nl.greenchoice.starsky/
├── Library/
│   └── Application Support/
│       └── starsky/
│           └── connect.sqlite          ← shared GRDB database
└── Documents/
    └── sync/                           ← synced files root
        └── <folder-id>/
            ├── photo.jpg
            └── .starskyconnect_tmp/    ← BlockStore temp files
```

**Resolving the container URL:**

```swift
extension URL {
    static var appGroupContainer: URL {
        FileManager.default
            .containerURL(forSecurityApplicationGroupIdentifier: "group.nl.greenchoice.starsky")!
    }

    static var connectDatabase: URL {
        appGroupContainer
            .appending(components: "Library", "Application Support", "starsky", "connect.sqlite")
    }

    static var syncRoot: URL {
        appGroupContainer.appending(components: "Documents", "sync")
    }
}
```

**Required entitlements** (add to both the main app target and any extension target):

```xml
<key>com.apple.security.application-groups</key>
<array>
    <string>group.nl.greenchoice.starsky</string>
</array>
```

**GRDB database queue must be opened with WAL mode** so the main app and a File
Provider Extension can both read/write without blocking each other:

```swift
var config = Configuration()
config.prepareDatabase { db in
    try db.execute(sql: "PRAGMA journal_mode = WAL")
}
let dbQueue = try DatabaseQueue(path: URL.connectDatabase.path, configuration: config)
```

**Keychain sharing** — the `SecIdentity` must be accessible from extensions
too. Add `kSecAttrAccessGroup` when storing the identity:

```swift
let query: [String: Any] = [
    kSecClass as String:            kSecClassIdentity,
    kSecAttrLabel as String:        "starsky-connect-identity",
    kSecAttrAccessGroup as String:  "group.nl.greenchoice.starsky",
    kSecValueRef as String:         identity,
]
```

## Local discovery multicast entitlement

`NWConnectionGroup` (the modern multicast API in Network.framework) requires
the `com.apple.developer.networking.multicast` entitlement on iOS.

**This entitlement is not automatically granted.** Apple reviews it manually.
To request it:
1. File a request at [developer.apple.com/contact/request/networking-multicast](https://developer.apple.com/contact/request/networking-multicast)
2. Justify the use case ("peer-to-peer file sync over LAN without a server")
3. Approval typically takes 1–2 weeks; it may be denied for consumer App Store apps

**Required entitlements** (only after approval):

```xml
<key>com.apple.developer.networking.multicast</key>
<true/>
```

**`NWConnectionGroup` usage** (once the entitlement is granted):

```swift
let multicastGroup = try NWMulticastGroup(
    for: [.hostPort(host: "239.255.68.42", port: 21027),
          .hostPort(host: "ff12::8384",     port: 21027)])
let params = NWParameters.udp
let group = NWConnectionGroup(with: multicastGroup, using: params)

group.setReceiveHandler(maximumMessageSize: 1500, rejectOversizedMessages: true) {
    message, content, isComplete in
    guard let data = content else { return }
    // parse BEP announce: 4-byte magic + protobuf BepAnnounce
}
group.start(queue: .global())
```

**Fallback when the entitlement is absent** (or during development before approval):

- Disable `LocalDiscovery` at runtime if the entitlement is missing
- Log a warning: "Local discovery unavailable — multicast entitlement not present"
- Fall back to manual address entry in the Connect preferences UI
- Use a compile-time flag `#if MULTICAST_ENABLED` to gate the `NWConnectionGroup` code so
  the binary submitted without the entitlement does not contain the call at all

```swift
// ConfigStore flag
var localDiscoveryEnabled: Bool {
    #if MULTICAST_ENABLED
    return true
    #else
    return false
    #endif
}
```

## Unix file permissions

```swift
// After assembling a file, restore BEP permission bits on non-macOS-sandboxed paths.

func restorePermissions(at url: URL, bepPermissions: UInt32) throws {
    #if !os(iOS)
    let mode = mode_t(bepPermissions & 0x1FF)
    guard mode != 0 else { return }
    try FileManager.default.setAttributes(
        [.posixPermissions: Int(mode)], ofItemAtPath: url.path)
```

## Open questions for implementation

1. **Multicast on iOS**: `NWConnectionGroup` supports multicast from iOS 14 but
   requires the `com.apple.developer.networking.multicast` entitlement (not
   automatically granted; requires Apple approval for App Store). Evaluate
   whether local discovery is worth the entitlement overhead, or fall back to
   manual address entry only.

2. **File Provider Extension**: a `NSFileProviderExtension` target would let
   synced files appear in the Files app without the main app running. This is a
   natural phase 2 once the core sync engine is stable.

3. **Relay client**: the relay wire format (magic `0x9E79BC40`, XDR-serialised
   payloads, ALPN `bep-relay`) is a separate protocol from BEP and is not
   covered in this spec. Add it as phase 2 alongside global discovery.

4. **Encrypted folders** (`FOLDER_TYPE_RECEIVE_ENCRYPTED`): the `FileInfo.encrypted`
   payload is out of scope for the initial port.

5. **Key rotation**: the current design generates one identity per device,
   forever. Define a Keychain label scheme before shipping if key rotation will
   ever be needed.
